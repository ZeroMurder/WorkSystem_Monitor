1. Private Bytes — виртуальная память, выделенная только процессу (куча, стек, приватные страницы), без разделяемых DLL/mapped-файлов. Утечку ловят по нему: при утечке память выделяется и не освобождается → счётчик монотонно растёт без возврата к базовой линии. Working Set включает разделяемые страницы и колеблется из-за кэша/подкачки, маскируя утечку. Рост Private Bytes «ступеньками» = сигнатура утечки (не освободили память, потеряли ссылку, циклические ссылки).

2. Paging: виртуальная память делится на страницы (4 КБ), часть в ОЗУ, часть в pagefile на диске. Обращение к странице не в ОЗУ → page fault → ядро вытесняет фрейм и читает нужную страницу с диска. При резком росте Page Faults/sec: диск на порядки медленнее ОЗУ, растёт время ожидания I/O; при избытке фолтов — thrashing, система тратит время на свопинг вместо вычислений → резкое падение производительности.

3. 0xc0000005 = STATUS_ACCESS_VIOLATION — нарушение прав доступа к памяти. Ошибки: разыменование NULL/dangling-указателя, выход за границы массива/буфера, use-after-free, запись в read-only область (строковый литерал), повреждение указателя/переполнение стека. Программа обратилась к адресу без прав или несуществующему.

CALS/ИПИ строится на структурированных машиночитаемых данных: XML парсится автоматически, грузится в БД/PLM/ALM, обеспечивает трассируемость и обмен между системами, статистику и аналитику по множеству падений, привязку к версиям/коммитам, долговременное хранение и поиск. Скриншот не парсится, не сортируется, не масштабируется, не проверяется автоматически.
